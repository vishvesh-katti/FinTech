SECTION 0: PROJECT OVERVIEW & PHILOSOPHY
================================================================================

WHAT THIS PRODUCT DOES:
RetailQuant is a personal finance intelligence tool. Most banking apps show you
only your current account balance. The problem is: that number is misleading.
It includes money you MUST spend soon (rent, EMI, subscriptions) and money you
SHOULD keep as a safety cushion. RetailQuant strips all of that away and shows
you one crystal-clear number: your "Deployable Surplus" — the money that is
genuinely free for you to invest right now without risk.

It then connects that surplus to live Indian market data (Nifty 50) and tells
you mathematically whether your investment goal is realistic.

THE CORE FORMULA (the heart of the product):
Deployable Surplus = Current Balance
                   - Fixed Obligations (rent, EMI, subscriptions due next 30 days)
                   - Variable Expense Buffer (avg monthly variable spend × 1.15)
                   - Emergency Fund Reserve (₹25,000 hardcoded baseline)

THE USER JOURNEY IN ONE PARAGRAPH:
A user uploads their bank statement CSV. The system reads every transaction,
uses an AI model to label each one (e.g., "Zomato → Food, not fixed" or
"HDFC EMI → Loan, fixed obligation"). It then runs the formula above, displays
the result on a clean dashboard, and lets the user type in a wealth target
(e.g., "I want ₹5,00,000 in 3 years"). The system calculates the exact annual
return rate (CAGR) they would need to hit that goal from their current surplus
and compares it to the Nifty 50's real historical performance.

SECTION 7: data_ingestion.py — CSV Reader & Cleaner
================================================================================

PURPOSE:
This module reads the CSV bank statement, cleans it up, and prepares it for
the AI parser. It handles messy real-world CSV quirks.

FUNCTIONS TO WRITE:

--- FUNCTION 1: load_transactions(filepath) ---
INPUT: filepath (string) — path to the CSV file
OUTPUT: A Pandas DataFrame with cleaned data

STEP BY STEP LOGIC:
1. Read the CSV using pandas.read_csv().
2. Handle the case where the CSV might not exist — raise a clear FileNotFoundError
   with message: f"Cannot find transaction file at: {filepath}"
3. Strip all leading/trailing whitespace from column names.
4. The "Withdrawal" and "Deposit" columns may have empty cells (NaN).
   Fill all NaN values in both columns with 0.
5. Convert the "Withdrawal" column to float type.
6. Convert the "Deposit" column to float type.
7. Convert the "Date" column to proper datetime objects using
   pandas.to_datetime() with format="%Y-%m-%d". Handle errors with
   errors='coerce' (bad dates become NaT).
8. Drop any rows where the Date is NaT (bad date rows).
9. Add a new column called "is_outflow": True if Withdrawal > 0, False otherwise.
10. Add a new column called "amount": equal to Withdrawal if is_outflow is True,
    equal to Deposit if is_outflow is False.
11. Rename the column "Narration" to "raw_description".
12. Return only these columns in this order:
    ["Date", "raw_description", "amount", "is_outflow"]
13. Reset the DataFrame index so it starts from 0.

--- FUNCTION 2: get_summary_stats(df) ---
INPUT: A cleaned Pandas DataFrame from load_transactions()
OUTPUT: A Python dictionary

WHAT IT CALCULATES:
- "total_rows": total number of transaction rows
- "total_deposits": sum of the "amount" column where is_outflow is False
- "total_withdrawals": sum of the "amount" column where is_outflow is True
- "date_range_start": the earliest date as a string in "YYYY-MM-DD" format
- "date_range_end": the latest date as a string in "YYYY-MM-DD" format

Return this as a Python dictionary.

SECTION 9: calculators.py — The Deployable Surplus Math Engine
================================================================================

PURPOSE:
This is the core mathematical brain of RetailQuant. It takes transaction data
and computes the Deployable Surplus — the safe-to-invest amount.

--- FUNCTION 1: calculate_dynamic_surplus(transactions_df) ---
INPUT: An enriched Pandas DataFrame (output of ai_parser.parse_all_transactions)
OUTPUT: A Python dictionary with all computed values

STEP BY STEP CALCULATION LOGIC:

STEP A — CURRENT BALANCE:
Formula: sum of all deposits (is_outflow == False) MINUS sum of all withdrawals
         (is_outflow == True)
Variable name: current_balance

STEP B — FIXED OBLIGATIONS (NEXT 30 DAYS):
Definition: These are payments the user is CERTAIN to make next month because
they happen every single month (rent, loan EMIs, subscriptions).
Logic:
1. Filter the DataFrame: keep only rows where is_fixed_obligation == True
   AND is_outflow == True.
2. Group by "clean_name" (or "category").
3. For each unique fixed obligation, take the AVERAGE monthly amount
   (total amount for that obligation / number of months it appears).
4. Sum all these averages together.
Variable name: fixed_obligations_next_30_days

STEP C — VARIABLE EXPENSE BUFFER:
Definition: Average monthly variable spend with a 15% safety buffer added.
Logic:
1. Filter the DataFrame: keep only rows where is_fixed_obligation == False
   AND is_outflow == True.
2. Determine the number of months in the data (difference between max date and
   min date, divided by 30, rounded up to at least 1).
3. Calculate total variable spend / number of months = average monthly variable.
4. Multiply by 1.15 (add 15% buffer).
Variable name: variable_expense_buffer

STEP D — EMERGENCY FUND:
Hardcoded constant: ₹25,000
Variable name: emergency_fund = 25000

STEP E — DEPLOYABLE SURPLUS:
Formula: current_balance - fixed_obligations_next_30_days
         - variable_expense_buffer - emergency_fund
Variable name: deployable_surplus

CRITICAL RULE: deployable_surplus must NEVER go below 0. If the formula
produces a negative number, set deployable_surplus = 0.

RETURN VALUE (dictionary with ALL these keys):
{
    "current_balance": <float>,
    "fixed_obligations_next_30_days": <float>,
    "variable_expense_buffer": <float>,
    "emergency_fund": 25000,
    "deployable_surplus": <float>,
    "is_surplus_zero": <boolean — True if the surplus was clamped to 0>,
    "breakdown": {
        "fixed_items": <list of dicts: [{"name": str, "amount": float}]>,
        "variable_categories": <list of dicts: [{"category": str, "monthly_avg": float}]>
    }
}

The "breakdown" key is important for the dashboard pie chart.
"fixed_items" should list each recurring obligation by name and its monthly cost.
"variable_categories" should list each variable category and its average monthly spend.

--- FUNCTION 2: format_inr(amount) ---
INPUT: A float number (e.g., 43500.75)
OUTPUT: A formatted string in Indian Rupee format (e.g., "₹43,500.75")
LOGIC: Use Python's locale or manual string formatting to insert commas at
Indian number positions (e.g., 1,00,000 not 100,000).

SECTION 10: market_routing.py — Market Data & CAGR Calculator
================================================================================

PURPOSE:
This module fetches live Nifty 50 data and helps the user understand whether
their wealth target is realistic given their deployable surplus.

--- FUNCTION 1: fetch_nifty50_1year_data() ---
INPUT: None
OUTPUT: A Pandas DataFrame with at least a "Close" column and a DatetimeIndex

LOGIC:
1. Use yfinance.download() to fetch data for ticker "^NSEI".
2. Set period="1y" (1 year of historical data).
3. Set auto_adjust=True.
4. If the download returns an empty DataFrame, raise a ConnectionError with
   message: "Could not fetch Nifty 50 data. Check your internet connection."
5. Return the DataFrame.

--- FUNCTION 2: calculate_nifty50_1year_return(nifty_df) ---
INPUT: The DataFrame from fetch_nifty50_1year_data()
OUTPUT: A float representing the percentage return (e.g., 0.15 means 15%)

LOGIC:
1. Get the first available "Close" price (oldest date in the DataFrame).
2. Get the last available "Close" price (most recent date in the DataFrame).
3. Calculate: (last_price - first_price) / first_price
4. Return this as a float (e.g., 0.1523 for 15.23% return).

--- FUNCTION 3: calculate_required_cagr(current_surplus, target_amount, years) ---
INPUT:
    - current_surplus: float — the deployable surplus in rupees
    - target_amount: float — the wealth target in rupees
    - years: int or float — the time horizon in years
OUTPUT: A float representing the required annual return rate

FORMULA: CAGR = (target_amount / current_surplus) ^ (1 / years) - 1

EDGE CASES:
- If current_surplus <= 0, raise a ValueError with message:
  "Cannot calculate CAGR: Deployable surplus is zero or negative. You need
   more free capital before you can work toward an investment target."
- If years <= 0, raise a ValueError with message:
  "Cannot calculate CAGR: Time horizon must be greater than zero."
- If target_amount <= current_surplus, return 0.0 (no growth needed).

--- FUNCTION 4: evaluate_market_viability(required_cagr, nifty_1yr_return) ---
INPUT:
    - required_cagr: float — from calculate_required_cagr()
    - nifty_1yr_return: float — from calculate_nifty50_1year_return()
OUTPUT: A Python dictionary

LOGIC:
Compare the required CAGR against the Nifty 50's actual 1-year return.
    - If required_cagr <= nifty_1yr_return: the Nifty 50 index is historically
      sufficient to meet the goal.
    - If required_cagr > nifty_1yr_return but <= 0.18 (18%): the goal is
      aggressive but potentially achievable with active equity funds.
    - If required_cagr > 0.18 (18%): the goal is very high-risk or
      unrealistic with standard market instruments.

RETURN VALUE:
{
    "required_cagr": <float>,
    "nifty_1yr_return": <float>,
    "is_index_viable": <boolean>,
    "viability_label": <string: "Conservative", "Moderate", or "Aggressive">,
    "viability_message": <string: a human-readable explanation>
}

viability_message examples:
- Conservative: "Your target can be met by simply investing in a Nifty 50
  index fund. This is a low-risk, hands-off strategy."
- Moderate: "Your target requires returns slightly above the Nifty 50 average.
  Consider actively managed large-cap or flexi-cap mutual funds."
- Aggressive: "Your target requires very high returns. This level of growth
  involves significant risk. Consider extending your time horizon or
  reducing your target amount."

SECTION 18: COMMON ERRORS & HOW TO FIX THEM
================================================================================

ERROR: "ModuleNotFoundError: No module named 'supabase'"
FIX: Run "pip install -r requirements.txt" again. Make sure you are in the
correct folder (the retailquant root folder) when running pip.

ERROR: "ValueError: SUPABASE_URL is missing from your .env file"
FIX: Open your .env file and make sure SUPABASE_URL is present and has a real
value (not placeholder text like "paste_here").

ERROR: "openai.AuthenticationError: Incorrect API key provided"
FIX: Your OPENAI_API_KEY in the .env file is wrong or expired. Go to
https://platform.openai.com/api-keys to get a new one.

ERROR: "ConnectionError: Could not fetch Nifty 50 data"
FIX: You are offline or yfinance is being blocked. Check your internet
connection. The tests for market data use mocking and should pass offline.

ERROR: "FileNotFoundError: Cannot find transaction file at: mock_transactions.csv"
FIX: Make sure mock_transactions.csv is in the root project folder (same level
as app.py). The tests assume you are running pytest from the root folder.

ERROR: Tests fail with "assert 85550.0 == pytest.approx(85550.0)" when they
should pass.
FIX: Your mock DataFrame in the test fixture might have slightly different
amounts. Recalculate the expected value based on your exact fixture data and
update the assertion.
